Agent micropayments: USDC micropayments for APIs

Agent micropayments are the missing business model of the AI economy: tiny per-call payments — 1¢, 5¢, 25¢ — that AI agents pay to APIs over HTTP 402 payments. No subscriptions, no API keys, no $20/mo seats for a bot that makes three calls. NanoTab settles USDC micropayments on Base mainnet at a flat 0.1% self-host (2% managed gateway), and every agent carries its own AI agent wallet.

Why micropayments, why now

Credit-card rails can't price below ~$1 (Stripe's 30¢ fixed fee kills it). Stablecoins on L2s can: a 1¢ USDC transfer costs a fraction of a cent in gas, and a paymaster can sponsor even that. The x402 protocol turns this into a web standard — 402 Payment Required, machine-readable, payable by humans and agents alike. Sellers finally get true pay-per-call billing; buyers finally pay only for what they use.

How it works in 30 seconds

npm i @nanotab/agent-sdk
  1. Seller prices an endpoint (e.g. 5¢) and returns 402 with the price to unpaid callers.
  2. Agent wallet signs a USDC intent and retries with X-Payment — one SDK call.
  3. Facilitator verifies and proxies; seller keeps 99.9%, settled instantly.

FAQ

What are agent micropayments?
Tiny per-call payments (from 1¢) that AI agents make to APIs via HTTP 402 — no subscriptions or API keys. NanoTab settles them in USDC at 0.1% self-host (2% managed gateway).
What is an AI agent wallet?
A wallet controlled by an agent holding USDC for autonomous payments. NanoTab's SDK handles signing, budget caps, and spend logging.
How do HTTP 402 payments work?
Server returns 402 with a machine-readable price → buyer signs USDC and retries with X-Payment → facilitator verifies and proxies to the origin.
